# 北科入口網站小幫手

![版本](https://img.shields.io/badge/版本-20260908.2-blue)
![兼容性](https://img.shields.io/badge/兼容性-Tampermonkey-green)
![推論](https://img.shields.io/badge/推論-100%25_本地-orange)

臺北科技大學校園入口網站（`nportal.ntut.edu.tw`）的增強小幫手，把常用功能整合成一支腳本：

1. **驗證碼自動辨識登入** — 於瀏覽器本地用 CNN 自動辨識登入驗證碼，走正規 web 登入，直接進入 **2026 改版後的新版 `cloudPortal` 介面**。
2. **保持登入（可選）** — 防止閒置 30 分鐘後被自動登出。
3. **OAuth2 授權登入頁自動填驗證碼** — 第三方服務導向 `oauth2Server.do` 時，自動把驗證碼填好；帳密與送出留給你自己。
4. **網路請購系統自動填驗證碼** — 主計室請購系統（`account.ao.ntut.edu.tw`、`accweb.ifirst.ntut.edu.tw`）的登入頁，同樣只填驗證碼。

四個功能純本地運作、**不呼叫任何外部 API、不上傳任何資料**。

## 功能一：驗證碼自動辨識登入

學校改版後，入口網從 `myPortal.do` 換成 `cloudPortal.do` 的新介面，而新介面必須走 **web session**、其驗證碼是**後端驗證**的（無法跳過，只能辨識）。本腳本在登入頁自動完成辨識與登入。

**運作原理**：驗證碼每個字是不同飽和色 → 用顏色把 4 個字乾淨切開（濾掉背景/交叉線/星點）→ 各字裁進 40×40 二值圖 → 每字 CNN（約 190KB float16 權重內嵌）辨識為 A–Z → 帶頁面 dojo Blowfish 加密的密碼 POST `login.do`；辨識失敗自動刷新重試（最多 6 次），連續失敗才回退手動輸入。

**準確率**：真實驗證碼單張辨識 char ≈ 98% / 整組 ≈ 94%，配合自動重試實際成功率 ≈ 99.99%。

模型以「合成預訓練 + 真實驗證碼（ddddocr 自動標註約 6,800 張）微調」訓練；管線與權重見 [`training/`](training/)。

**登入後的跳轉**：入口網的 `login.do` 不走 HTTP 302，而是回一段 HTML、在裡面用 JS 的 `location.href` 指定下一步。腳本因此不自行猜測目的地，一律跟隨伺服器的指示——密碼過期強制修改、手機簡訊驗證、服務條款同意等後續流程都會原樣呈現，交由入口網自己的頁面接手。

## 功能二：保持登入（預設關閉）

入口網有 30 分鐘閒置自動登出。勾選後，腳本會定時呼叫入口網自己的 `resetTime()` 把閒置計時器歸零（並自動關掉「即將登出」警告框），伺服器 session 由入口網既有的 `sessionCheck` 保活——只要開著分頁就不會因閒置被登出。

- **預設關閉**：在登入頁的「🤖 驗證碼自動辨識」狀態卡上有一個「**保持登入**」勾選框，勾選後會記住（`localStorage`）。
- 只擋「閒置逾時」；若學校另設「絕對最長 session」則無法避免。
- 公用電腦請斟酌是否開啟。

## 功能三：OAuth2 授權登入頁自動填驗證碼

第三方服務（例如學校官網的會員登入）會把你導到 `nportal.ntut.edu.tw/oauth2Server.do`，那是另一個帶驗證碼的登入頁。它用的驗證碼端點是 `dacAuthImage.do`，**與功能一的 `authImage.do` 完全不同**：4 碼純大寫 A–Z、不旋轉不扭曲沒有雜訊，而且每個字形每次渲染的點陣圖完全一致。

因此這裡**不需要 CNN**——26 個字母各存一張點陣圖，逐位元比對就能辨識。實測 110 張真實驗證碼切出的 440 個字元恰好收斂成 26 種點陣圖（A–Z 各一），另取 20 張全新驗證碼驗證 20/20 正確。模板約 1KB，這頁也不會去解碼功能一那 253KB 的 CNN 權重。

**只填不送**：腳本把辨識結果填進驗證碼欄就停手，帳號、密碼、「登入」按鈕都由你自己操作。辨識失敗會自動換一張重試（最多 6 次），仍失敗就留空給你手動輸入；你按頁面上的「重整」也會重新辨識。

辨識時直接讀畫面上已顯示的那張圖，不另外發請求——每次請求 `dacAuthImage.do` 都會換一組答案，另外抓會導致畫面上的圖和填入的答案對不起來。

## 功能四：網路請購系統自動填驗證碼

主計室的**網路請購系統**（`account.ao.ntut.edu.tw/APSWIS_Q/`）也有驗證碼，而且和入口網那套毫無關係：**124×24 只有兩色、5 碼、折線手繪字體、單像素鹽粒雜訊**，字集只有 22 類（`123456789 BCDHIJKLMNPRX`，沒有 `0` 也沒有 `AEFGOQSTUVWYZ`）。

**運作原理**：去掉小於 20px 的連通元件濾掉鹽粒 → 用 **8-連通元件**切字（不是垂直投影）→ 各字裁進 40×40 → 每字 CNN 辨識為 22 類。模型與功能一同架構，但全連接層減半（cf1 從 64 降到 32），權重 151KB。

**兩個門檻都不需要調參**，因為資料本身是分離的：雜訊與筆畫的元件大小空隙是 6–53px、單字與相黏雙字的寬度空隙是 29–34px，中間完全沒有樣本。

**準確率**：60 張全新驗證碼整串 60/60、字元 300/300（95% 單側信賴下界：整串 95.1%、字元 99.0%）。約 10% 的圖會有兩字相黏而切不開——**偵測到就換一張重抓**（最多 6 次，全失敗機率百萬分之 1.6），不做切割演算法。

**只填不送**：請購送單不可逆，腳本只把驗證碼填進欄位，帳號密碼與「確定」按鈕都由你自己操作。頁面本身的「重整」按鈕是 `RE_PAGE()`、會整頁重載並清掉已輸入的帳密，所以腳本重試時是自己換圖片網址，不動你打好的東西。

### 兩個主機，兩套驗證碼

請購系統有多個主機，介面看起來一模一樣，但**驗證碼產生器不同**，這點很容易誤判：

| 主機 | 端點 | 驗證碼 |
|---|---|---|
| `account.ao.ntut.edu.tw` | `ValidCode.asp` | 124×24 黑色折線、**5 碼英數**、22 類 |
| `accweb.ifirst.ntut.edu.tw` | `ValidCode_2.asp` | 60×10 **紅色數字**、**6 碼**、10 類 |

所以腳本**用驗證碼圖片的網址、而不是主機名**來決定用哪個模型——日後再多一個主機也會自動挑對。（`ValidCode.asp` 在 ifirst 上其實也存在，但登入頁根本不用它；如果照主機名硬套，就會自信地填錯答案。）

紅色數字那套的模型只有 66KB（10 類、16×16 輸入）：數字高度一律 10px、雜訊碎片只有 1–5px，中間 6–9 完全沒有樣本，所以切字改用**高度**過濾，實測 600 張零失敗。60 張全新驗證碼整串 60/60、字元 360/360。

> 完整的研究過程、實測數據與訓練管線見 NTUT_Tools 的 `docs/apswis_captcha_ocr.md`。

## 安裝

1. 安裝 [Tampermonkey](https://www.tampermonkey.net/) 瀏覽器擴展
2. 點擊下方安裝連結，Tampermonkey 會自動識別並提示安裝

[![安裝腳本](https://img.shields.io/badge/安裝腳本-Greasy_Fork-blue)](https://update.greasyfork.org/scripts/591763/%E5%8C%97%E7%A7%91%E5%85%A5%E5%8F%A3%E7%B6%B2%E7%AB%99%E5%B0%8F%E5%B9%AB%E6%89%8B.user.js)
[![Greasy Fork 頁面](https://img.shields.io/badge/Greasy_Fork-腳本頁面-670000)](https://greasyfork.org/zh-TW/scripts/591763)

安裝後到 `nportal.ntut.edu.tw` 登入頁，輸入帳號密碼按登入即可（驗證碼欄已變成自動辨識狀態卡）；需要保持登入就勾一下卡片上的選項。

## 隱私與安全

- **全程本地**：驗證碼圖片只在你的瀏覽器內處理，不上傳任何伺服器。
- **無外部依賴**：模型權重內嵌於腳本，不從任何 CDN／gist 下載。
- 帳號密碼只送往學校官方 `login.do`，與正常登入相同。
